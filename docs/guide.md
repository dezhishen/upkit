## 安装与首次启动

1. 从 [Releases](https://github.com/dezhishen/upkit/releases) 下载 `upkit-windows-amd64.exe`
   （ARM 设备选择 `arm64`）。

2. 将程序放在一个固定目录下，例如 `D:\软件\upkit\`。
   不建议放在 `C:\Program Files\` —— 该目录需要管理员权限才能写入。

3. 双击运行。首次启动会自动创建所需目录。

启动后显示全屏界面，共五个面板，编号 `1` 到 `5`；「详情」不在标签行上，它是概览的
下级页面（选中软件按回车进入，`esc` 返回）。

**首次启动时列表为空**：upkit 不内置软件，需先添加源。

## 界面说明

窗口标题栏显示工具名与版本号，界面顶部一行是面板标签与软件数量统计：

| 面板 | 内容 |
| --- | --- |
| **1 概览** | 全部受管软件，每行显示名称、状态、当前版本与最新版本（<kbd>Enter</kbd> 进详情） |
| **2 任务** | 下载与安装任务及其进度 |
| **3 日志** | 操作记录，故障时优先查看 |
| **4 设置** | 代理、下载限速、备份保留份数、配色方向等 |
| **5 来源** | 已添加的源及其插件 |

窗口较窄时，数量统计会让位给面板标签。

**操作栏**：每个面板底部都有一行操作栏，列出当前能做的事，键名就在按钮上
（`[c] 检查`）。鼠标点按钮即可执行，也可以直接按那个键 —— 所以不必先记住快捷键。

**鼠标**：点标签切面板、点一行选中、同一行再点一次（双击）= 打开/编辑、滚轮滚动列表、
点操作栏按钮执行、弹窗上的「确定/取消」也能点。若你更需要终端原生的拖选复制与右键
粘贴，用 `--no-mouse` 启动（鼠标上报会接管这些操作）。

按 <kbd>1</kbd> 至 <kbd>5</kbd> 切换面板，按 <kbd>Tab</kbd> 依次切换，或直接点标签。
按 <kbd>?</kbd> 查看完整键位。

### 配色

界面配了两套颜色，语义一致：绿=最新、橙=可更新（或运行中）、红=冲突或失败、
蓝=可操作、灰=次要信息（路径、时长、已停用）。

- 默认 `auto`：白底终端用浅色一套，深色终端用深色一套。判据是终端的 `COLORFGBG`
  环境变量；它没设或设得不标准时按深色处理 —— 大多数终端是深底。
- 判错了就强制指定：命令行 `--theme light`（或 `dark`），或在设置文件的
  `ui.theme` 里写死（`auto` / `dark` / `light`）。
- 重定向到文件或 `--no-color` 时只保留字重，不输出颜色码，日志文件与管道里不会出现
  转义字符。

### 命令行选项

| 选项 | 作用 |
| --- | --- |
| `--config 路径` | 指定设置文件 |
| `--log-level 级别` | `debug` / `info` / `warn` / `error`，覆盖设置文件 |
| `--log-dir 路径` | 日志目录 |
| `--no-color` | 禁用颜色输出 |
| `--theme auto\|dark\|light` | 配色方向：`auto`（跟随终端背景）为默认，覆盖设置文件里的 `ui.theme` |
| `--ascii` | 仅用 ASCII 字符绘制界面 |
| `--no-mouse` | 关闭鼠标支持，保留终端原生的拖选复制与右键粘贴 |
| `--focus` | 以无标题栏的焦点模式重新启动，见下一节 |
| `--print-paths` | 打印目录布局与设置文件位置后退出 |
| `--version` | 打印版本后退出 |

## 去掉窗口标题栏

upkit 运行在终端里，窗口的标题栏与标签行由终端绘制，**程序自身无法隐藏它们**。
不过 Windows Terminal 提供了「焦点模式」，进入后连标题栏与标签行一起隐藏，只剩界面内容。有两种用法：

**每次启动都无标题栏**（推荐）：

1. 在 Windows Terminal 中按 <kbd>Ctrl</kbd>+<kbd>,</kbd> 打开设置，
   或直接编辑 `settings.json`。
2. 在**根节点**（不在任何 `profiles` 条目里）加上：

   ```json
   "launchMode": "focus"
   ```

   数值也可用 `"maximizedFocus"`：最大化且无标题栏。
3. 重启 Windows Terminal 生效。

**只对某次启动生效**：从命令行启动时加 `--focus`：

```cmd
upkit.exe --focus
```

upkit 会请 Windows Terminal 以焦点模式另开一个窗口，然后退出当前进程。
注意：

- 只在 Windows Terminal 中有效。在传统控制台里运行会直接报错，
  此时可先按 <kbd>Alt</kbd>+<kbd>Enter</kbd> 进入全屏。
- 需要 `wt.exe` 可用（Windows Terminal 默认启用其应用执行别名）。
- 会另开一个窗口，原窗口关闭，因此屏幕会闪一下。
- 想临时退出焦点模式，用 Windows Terminal 的 `toggleFocusMode` 动作；如需随时切换，可在 `settings.json` 的 `actions` 里给它绑定一个快捷键。

## 添加与管理软件

### 第一步：添加源

按 <kbd>5</kbd> 进入「来源」面板：

- 按 <kbd>o</kbd> 添加官方源（推荐）
- 或按 <kbd>a</kbd> 填入自定义源地址

添加后 upkit 会拉取该源，并列出其中的插件。

### 第二步：启用插件

插件**默认未启用**，需确认后手动启用 —— 插件为可读写本机文件的可执行程序，来源不可信时存在风险。

启用方法：按 <kbd>空格</kbd>。若界面要求填入确认字符串，可在「日志」面板（按 <kbd>4</kbd>）中查看。

> 该字符串是安装包的校验值。与发布者公布的一致，即表示文件未被篡改。

### 第三步：返回概览

按 <kbd>1</kbd> 返回，列表中将显示该源提供的软件，每行包含软件名、当前版本与最新版本。

显示「待安装」表示该软件尚未安装。

## 日常操作

### 检查更新

在「概览」面板中，按 <kbd>c</kbd> 检查选中项，按 <kbd>C</kbd> 检查全部。

检查仅查询各软件的最新版本，不下载文件。

### 更新

按 <kbd>u</kbd> 更新选中项，按 <kbd>U</kbd> 更新全部可更新项。

更新过程中可在「任务」面板（按 <kbd>3</kbd>）查看进度。流程为：

```
下载 → 校验 → 备份原文件 → 替换 → 收尾
```

任一步骤失败都会自动恢复至更新前状态，不会残留不完整结果。

### 预览变更

按 <kbd>p</kbd>。upkit 会列出执行计划，但不改动任何文件。

### 安装软件

在列表中选中显示「待安装」的软件，按 <kbd>u</kbd> 安装。

### 卸载

按 <kbd>x</kbd>。upkit 会询问是否保留数据：

- **保留**：删除软件本体，保留配置与用户数据，重新安装后继续沿用
- **不保留**：全部删除

### 回滚

按 <kbd>R</kbd> 恢复至最近一次更新前的状态。upkit 在每次更新前自动备份，该操作始终可用。

### 暂停更新

按 <kbd>空格</kbd> 停用选中软件。条目仍保留在列表中，但「检查全部」与「更新全部」会跳过它。

## 软件来源

upkit 不内置任何软件，全部来自**源**。

```
源  →  其中的插件  →  插件管理的软件
```

- **源**：填入地址，upkit 拉取并安装其中的插件
- **插件**：由源维护者提供，描述一组软件的下载地址、安装方式与版本判定规则
- **软件**：插件管理的软件，显示在概览列表中

列表中缺少所需软件时，应添加新的源。

可添加多个源，其软件合并显示。若两个源提供同一软件，upkit 会拦截冲突并提示冲突条目，需手动移除其中一个。

## 数据存放位置

默认采用便携模式：全部文件位于 upkit 同级目录，**整体复制到其它电脑即可继续使用**，无需重新配置。

```
config/    设置与源信息
log/       运行日志（按保留策略自动清理）
plugin/    已安装的插件
apps/      软件默认安装目录（插件没写明路径时）
data/      各插件的数据目录
cache/     已下载的安装包（保留以复用，避免重复下载）
backup/    更新前备份（按 <kbd>R</kbd> 恢复的来源）
temp/      更新过程中的临时文件（自动清理）
```

**迁移**：直接移动整个 upkit 目录。

**换位置**：在「设置」面板（<kbd>5</kbd>）里可以单独改**软件安装根目录**、数据、缓存、备份、临时、日志、插件这几个目录 —— 留空表示跟随根目录，适合把软件装到 `D:\Apps`、把占空间的 `cache/`、`backup/` 放到别的盘。改完按 <kbd>s</kbd> 保存，部分项重开程序后生效。

**软件装到哪**：插件在它的清单里写安装位置，其中 `${ROOT}` 指的就是「软件安装根
目录」；没写明路径的软件则装到 `<安装根目录>/<软件名>`。改安装根目录**不会搬动已
经装好的软件**，只影响之后的安装与检测。

**要求所有软件都在一个目录下**（例如全部装进 `C:\apps`）：把「软件安装根目录」
设成 `C:\apps`，再打开同一组里的**「全部装到安装根目录下」**开关。插件可能把目录
写死在自己的位置（如 `%LOCALAPPDATA%\...`），只改根目录对它们无效；打开这个开关
后，upkit 自己落地的软件（`portable` 方式）一律装到 `<安装根目录>/<软件名>`。

两点要知道：它只对 upkit 自己决定落点的软件生效 —— 由安装器（msiexec、安装程序）
或插件自己安装的软件，那个路径只是「去哪找它」，强行改会连检测都找不到；另外打开
开关后，**已经装在别处的软件会被看作「未安装」**，需要在新的根目录下重新落地一次
（旧的那份不会自动删除）。

根目录本身由启动方式决定（`UPKIT_HOME` 环境变量 > upkit 所在目录 > `%APPDATA%\upkit`），面板里只读：要换它就整体移动目录，或用 `--config` 指定新的设置文件位置。

**注意**：请勿将 upkit 放在需要管理员权限的目录（如 `C:\Program Files\`）。若放置在该处，upkit 会自动将上述目录迁移至 `%APPDATA%\upkit`，数据将不再与程序同级。

**空间清理**：`cache/` 与 `backup/` 占用最多。删除 `cache/` 后下次需重新下载；删除 `backup/` 后无法回滚至对应历史版本。二者均不影响正常运行。

## 故障排查

### 查看日志

按 <kbd>4</kbd> 打开「日志」面板。upkit 记录每一步操作，故障原因通常位于末尾几行。

日志中的密码与令牌会自动脱敏。

### 启动后立即退出 / 无法启动

- 确认系统为 64 位 Windows
- 确认安全软件未拦截。未签名的可执行文件可能被拦截，需手动放行
- 更换目录后重试，例如 `D:\upkit\`

### 更新失败

upkit 已自动恢复至更新前状态，软件可继续使用。

查看日志末尾确认原因，常见为：网络中断、下载地址失效、目标文件被占用。

### 提示目标软件正在运行

更新前需关闭目标软件。upkit 会尝试自动结束占用进程；若仍无法更新，请手动关闭后重试。

### 提示源冲突

两个源提供同一软件。在「来源」面板用 <kbd>空格</kbd> 停用其中一个，或从 `apps.yaml` 里删掉其中一个来源。

### 更新版本不符合预期

选中该软件，按 <kbd>p</kbd> 查看执行计划。若确为源配置错误，请联系该源的维护者。

### 重置配置

删除 `config/` 目录后重新启动，等同于首次运行。

已安装的软件不受影响，但需重新添加源。

## 常见问题

**需要联网吗？**
需要。检查更新、下载安装包、拉取源均需联网。可在「设置」面板中配置代理。

**会收集或上传数据吗？**
不会。upkit 仅发起下载请求，不上传任何数据。

**密码会被记录吗？**
不会。密码与令牌在写入日志前已自动脱敏。

**可以后台常驻吗？**
不可以。程序需保持运行，关闭窗口即停止。

**可以同时运行多个实例吗？**
不可以，第二次启动会提示已在运行。

**支持 Mac / Linux 吗？**
不支持，仅提供 64 位 Windows 版本。

**为什么列表中会出现未安装的软件？**
源会列出其描述的全部软件。未安装的显示为「待安装」，不会自动执行任何操作。

**如何迁移到另一台电脑？**
复制整个 upkit 目录即可，其中包含源、设置与备份。
